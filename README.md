# 项目星图

在接入写入守卫的会话里，AI 改代码前先发布本轮提案，指明要动哪个环节、涉及哪些文件。打开星图可以看见对应步骤高亮、拟改文件和提案说明。随仓库提供的首张图描述星图自身的这段实现，每一步都能定位到源码行。

## 本地查看

使用 Node.js 22.13 或更新版本，在仓库根目录运行：

```sh
node flow/preview.mjs --serve 57083
```

在浏览器中打开 `http://127.0.0.1:57083/`。滚轮放大后，视图依次展示三个层次：

1. **项目阶段**显示 AI 提交提案、保存范围、网页标注和写入检查之间的交接。
2. **内部步骤**展开各阶段，箭头说明相邻步骤传递的数据或事件。
3. **字段流向**追踪选中的字段。示例中的 `stepRefs` 从提案输入流向步骤卡片，金色表示字段经过的路径，其他步骤保留为上下文。

悬停连线可查看去向，点击连线可转到目标。步骤卡片的文件链接可在本机编辑器定位到源码行；如需指定兼容 VS Code 命令行参数的编辑器，可设置 `FLOW_EDITOR`。

## 在 AI 会话中启用改动前标注

守卫适配器位于 `plugins/dsh-flow/`。在自己的本地副本中，将该目录下 `cordis.patch.yml` 的占位会话 ID 替换成目标 DSH 会话 ID。默认项目根目录是本仓库，要绑定其他项目可在同一配置中设置 `projectRoot`。从 DSH 插件管理器安装并启用该 bundle，查看器和会话均须指向有 `flow/map.json` 的同一项目。

本轮写入前，由 AI 调用 `flow_publish`。下面的参数将示例图里的“高亮受影响步骤”标为本轮目标：

```json
{
  "phaseIds": ["viewer"],
  "stepRefs": [{"phaseId": "viewer", "stepId": "mark"}],
  "summary": "调整受影响步骤的高亮样式",
  "files": ["flow/viewer.html"]
}
```

工具校验引用，保存提案并登记本轮文件范围。网页轮询提案，显示「本轮提案 · 待实施」。在配置的会话中，发布前的 `edit` 和 `write` 会被拦截；发布后，目标文件仍须属于提案范围。网页刷新和工具放行分别执行，写入无需等待用户点击确认。新一轮或新的用户消息会使上一份回执失效。

适配器包含针对模拟宿主事件的回归测试。正式 DSH 桌面加载和模型调用仍需按实际宿主版本验证。运行测试：

```sh
node --test plugins/dsh-flow/index.test.js
```

## 发布其他项目的图

根据目标项目的代码整理地图草稿，每个步骤填写真实的项目相对路径和行号，每条边注明所传数据或事件。可以参考本仓库的 `flow/map.json`。

```sh
node flow/project-map.mjs <目标项目根目录> <地图草稿.json>
```

校验通过后发布器会更新目标项目的 `flow/map.json`。将项目登记在本机查看器的 `flow/projects.json` 中，页面的项目选择器即可手动切换。配置中的相对根路径以登记文件所在目录为基准。
